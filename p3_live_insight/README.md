# P3 · 直播切片洞察引擎

> 主线角色：**客服差异化升级**——把 P1 的直播转写变成可检索、可复用的「切片 + 商品 + 情感」结构化洞察，并回血知识库供 P2 检索，让直播话术沉淀为客服可用的知识。

## 一句话

一个把**直播口播转写**自动切成「商品介绍」粒度片段，并完成**摘要 / 情感 / 商品关联**的离线可复现流水线，每段回血一条 `knowledge_doc` 给 P2。

## 架构链路

```
直播转写文本（MinIO: live/*.txt）
  ├─ ① ASR（mock：直接读 .txt 转写；云端：阿里/腾讯录音文件识别）
  ├─ ② 语义分段（规则：主播开始介绍新商品即切段，未命中 → 互动/其他）
  ├─ ③ 摘要 + 情感（mock 抽取式摘要 / 规则情感；真实 LLM 生成式摘要）
  ├─ ④ 商品关联（embedding 余弦相似度 top1~2，阈值 0.2）
  ├─ ⑤ 落库 live_segment（MySQL）+ 回血 knowledge_doc（MinIO 正文）
  └─ ⑥ 资产 / 血缘 / 审计（live_session → live_segment → knowledge_doc）
```

## 运行

前置：`docker compose up -d`、`cp .env.example .env`、先跑 P1 供血（商品表有数据才能关联商品）。

```bash
uv run shopmind p1 run      # P1 供血（若还没跑）
uv run shopmind p3 run      # ASR→分段→摘要/情感/关联→回血知识库
uv run shopmind p3 list     # 列出历史切片
uv run shopmind p3 export   # 为每段生成多模态引用摘要（打印）
```

## 关键选型（面试逐条可展开）

| 决策点 | 选择 | 为什么 / 备选 |
| :--- | :--- | :--- |
| ASR | 云端录音文件识别（阿里/腾讯），mock 读 `.txt` | 直播是长音频离线任务，用文件转写 API 而非流式；离线 mock 保证无 Key 也能跑通 |
| 语义分段 | **规则：主播介绍新商品即切段**（关键词命中） | 零成本、结果确定、天然对齐时间戳（start_sec/end_sec 可直接剪视频）；备选 LLM 分段更懂语义但贵且边界不稳，可后续做「规则粗切 + LLM 精修」 |
| 摘要 | mock 抽取式（前 1~2 句裁剪），真实 LLM 生成式 | 抽取式离线可复现、零成本；生成式更口语化，上线切真实模型 |
| 情感 | 规则词典（好/不错/划算/推荐/放心 → positive，差/坏/问题/投诉/贵 → negative） | 快、可解释、无成本；局限是「晚上好」这类会误判，生产换 LLM 情感分类 |
| 商品关联 | **embedding 余弦相似度 top1~2，阈值 0.2** | 用语义而非字符串精确匹配，能关联同义/变体表述（“耳机”↔“真无线蓝牙耳机 X”）；阈值过滤弱相关，避免硬配 |
| 回血 | 每段一条 `knowledge_doc`（source_type=live_transcript） | 复用 P2 统一入库管线（切片→向量→ES），直播话术与政策/手册走同一条「数据→知识」链路 |

## 面试高频追问自查

1. “为什么分段用规则不用 LLM？”→ 规则零成本、结果确定、天然对齐时间轴（start_sec/end_sec 可直接剪视频）；LLM 在长文本上贵且边界不稳定。生产可「规则粗切 + LLM 摘要精修」。
2. “商品关联为什么用 embedding 而不是关键词？”→ 关键词会漏掉同义/变体表述；embedding 捕捉语义，top1~2 + 阈值 0.2 兼顾召回与精度。
3. “情感规则会误判吗？”→ 会，比如「晚上好」含“好”会被判正面；这是简单规则的已知局限，生产接 LLM 情感分类，规则仅做离线兜底。
4. “为什么每段回血成 knowledge_doc 而不是直接进 ES？”→ 复用 P2 的统一入库管线，直播切片与政策/手册走同一条「数据→知识」链路，便于统一检索和溯源。
5. “mock 模式下 cosine 相似度靠谱吗？”→ mock embedding 是 token 哈希桶累加，共享 token 越多相似度越高，只能验证链路；真实语义相似度需切真实 embedding 模型。
